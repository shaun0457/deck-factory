# 出事情境、證據列與兩種編號

假設 deck 已貼上 `kit:base`（用到 `abs`、`INK`、`BODY`、`MUTED`、`RULE`、`NEUTRAL`、`OK`、`MONO`）與 `kit:map`（`RIGHT_X`、`RIGHT_W`）。

| 元件 | 做什麼 |
|---|---|
| `LENSES` | 品質面向與顏色（資料一致性、API 行為、可靠度…），deck 自己定義 |
| `DesignBadge`、`DesignMark` | 方形墨色編號：「我的設計 N」（HTML 版／地圖 SVG 版） |
| `IncidentBadge` | 圓形編號，依品質面向上色：「出事情境 N」 |
| `ScenarioHead`、`ScenarioList`、`Scenario` | 三欄表：情境（＋編號）→ 系統怎麼做（＋機制）→ 測試名稱 |
| `Evidence` | 設計頁底部一列：「擋住」哪些情境（依顏色）＋「測試」哪些檔案 |

## 怎麼用（B 版的做法）

1. 全貌頁：系統圖上放 `DesignMark` 標出 N 個設計，右側列出每個設計（`DesignBadge`＋名稱＋品質面向）。
2. 每個設計頁：底部放 `<Evidence items={[...]} tests={[...]} />`，按 → 才出現。
3. 證明頁：`Scenario` 每列一個設計（`design={n}`），寫「怎麼做出這個狀況 → 測試」。編號和全貌頁一樣，聽眾對得起來。

## 教訓

- 方形＝設計、圓形＝情境，兩種編號一定要長得不一樣，否則聽眾會以為「設計 3」就是「情境 3」。
- 品質面向的顏色旁邊一定要有文字（色盲、黑白列印、投影機偏色）。`IncidentBadge` 和 `Evidence` 的標籤本身只有顏色，用它們的頁面要另外寫出面向名稱（例：全貌頁每個設計下面寫「資料一致性」），或放一個圖例。
- 證明頁原本照「品質面向」排，改成照「設計」排之後，和前面幾頁對得起來，好講很多。
- 升級進 kit 前要做：把座標（`top`）改成 props、在範例 deck 的證明頁用一次。
