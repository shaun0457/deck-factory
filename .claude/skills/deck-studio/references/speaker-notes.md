# 講稿怎麼寫

來源：2026-11 面試設計說明 B 版，主講 8 頁的講稿改了約 20 輪，最後定稿 7 分 25 秒。下面是每一輪被改掉的問題，寫的時候就照做。

## 先讓講者用自己的話講一次

1. Claude 先寫一版口語稿。
2. 講者照自己的說法重講或改寫一頁（「我會這樣講」）。
3. Claude 只做三件事：對事實、補漏掉的因果、刪重複；**不換回書面語**。
4. 一頁一頁來，一頁一個 commit，方便講者對照。

講者自己的句子比較好記，也比較不像在念稿。B 版第 2–7 頁的講稿最後都換成講者的說法。

## 每頁的結構

- **第一句白話**：先講這頁要回答的問題或結論，聽眾不用看投影片也聽得懂。
- **設計類頁面**照四步講：
  1. 出事情境（例：使用者連按兩次送出）
  2. 直覺的做法為什麼不行
  3. 我做了什麼
  4. 代價（選這個放棄了什麼）
- **最後一句**接到下一頁，或回到主線。
- 每頁開頭標時間「（約 N 秒）」；按 → 會出現東西時，在那一句前寫「（按 →）」。

## 用詞

- 聽眾裡有非技術的人時，講稿不講協定細節：說「送出請求」，不說「POST」；狀態碼（202、409、503）留在投影片和備用頁，講稿講它代表什麼（「先給回執」「這段對話正在忙」）。
- 一個比喻用到底，不要中途換（例：「回執」「一個廚房」「行李箱」各管一件事）。比喻和實際行為對不上的地方，要嘛修比喻，要嘛不用。
- 理由講直接的那一個（「題目只要求單台，所以先不用 queue」），不要先講抽象原則再繞回來。
- 選擇用題目的範圍來說明（「題目規定沒有登入」），比用個人偏好有說服力。
- 一個重點最多兩句短句。兩句講不完，就是這頁塞太多，移一部分到備用頁。
- 機制講它「做什麼」，不講它「叫什麼」（「舊的工作寫不回去」比「fencing token」好懂）。

## 誠實的部分要早講

- 沒做的事在前面就講（例：「公開部署沒有做」放在第 2 頁），不要等被問。
- 數字一定帶條件：在哪裡量的、樣本多少、換環境會不同。
- 有實作但沒實測的，講「介面相容、還沒實際接過」。
- 講稿任何人都看得到：不寫花了多久、有沒有用 AI、薪資、對聽眾的評價（見 `facts-and-privacy.md`）。這些答案寫在私人的 Q&A 筆記。

## 收尾

- 最後一頁講完就停：「以上，歡迎從任何一頁開始問。」不要再接一頁「謝謝」。
- 備用頁的講稿以「（備用：被問到…時）」開頭，第一句直接回答那個問題。

## 檢查

- `lint-deck` 算時間：主講加總要在目標內，超過就砍或移到備用頁。
- 講者實際念一次，念不順的句子標出來再改；以講者念的時間為準。
