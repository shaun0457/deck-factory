# 設計規則（open-slide kit 的數值）

## 畫布與格線（1920×1080）

| 名稱 | 值 | 用途 |
|---|---|---|
| `GUTTER` | 120 | 左右邊界 |
| `CONTENT_W` | 1680 | 內容寬 |
| 進度條 | y 40 | 有 `at` 的頁面才顯示 |
| eyebrow | y 116 | 章節名或「備用 · Pxx …」 |
| 標題 | y 160 | 主講頁 60 px（`MAIN_TITLE`），備用頁 76 px |
| `BODY_TOP` | 300 | 第一排內容 |
| `SOWHAT_TOP` | 880 | 一句結論（放大頁不用，內容可到 930） |
| Footer | y 1000 | 名稱、署名、頁碼 |

放大頁：縮小系統圖在 (120, 300)、寬 `MINI_W` 720；取捨卡 (120, 660, 720×270)；右欄 x `RIGHT_X` 900、寬 `RIGHT_W` 900。

## 字級

| 用途 | 大小 |
|---|---|
| 主講標題 | 60 |
| 卡片標題 | 32–44 |
| 內文 | 26–30（不要低於 24） |
| 標籤、表頭、註腳 | 20–24 |
| 等寬（程式名詞） | 19–24 |

## 每行字數估算（中文）

可用寬度 ÷ 字級 ≈ 每行中文字數；英數字約算半個字。例：取捨卡文字區 576 px、27 px → 每行約 21 字。超過就用 `<br />` 在語意斷點換行，不要讓瀏覽器斷在詞中間。

## 配色（Fieldwork）

- 墨色 `INK` 用於標題與線條；珊瑚 `CORAL` 每頁只強調一件事（eyebrow、編號、焦點框）。
- 卡片用淡色：`TINT_BLUE`、`TINT_GREEN`、`TINT_YELLOW`、`TINT_PINK`；同一個概念在整份 deck 用同一個顏色（例：受理永遠是藍、資料庫永遠是黃）。
- 虛線＝選用、未實測或還不存在；灰淡＝不是這頁的重點（`MAP_DIM` 0.25）。

## 系統圖

- 用約 1000 單位寬的座標設計（`MAP.view`），全貌頁畫 1100 px、縮小版 720 px。
- 節點 4–7 個；容器（frame）最多兩個。標題 30／縮小版 34 單位，副標 21 單位。
- 編號（hops）只在全貌頁顯示；縮小版預設關掉，避免一堆淡掉的小圓點。
- 疊加層：`MapLetter`（熱點 A/B/C）、`MapBoundary`（測試範圍）、`MapSticker`（標籤，30 單位字）、`MapGhost` / `MapLink`（還不存在的部分）。

## 動畫與揭露

- `Steps` 用在「按 → 依序出現」的清單（三種方式、三個情境）；講稿要寫明。
- 預覽與截圖會顯示所有 Steps；檢查版面時要以全展開為準。

## 編號與顏色的語意

- 兩種編號要長得不一樣：「我的設計」用方形墨色編號，「出事情境」用圓形、依品質面向上色。同一個編號在全貌頁、設計頁、證明頁都用同一個樣子。
- 品質面向一個顏色用到底（例：資料一致性、API 行為、可靠度、LLM 整合、測試品質各一色）；顏色旁邊一定有文字標籤。

## 截圖檢查清單

`check-layout` 抓得到的先跑腳本；下面是看截圖時要自己確認的。改寫自 ppt-master 的 visual-review（見 `ppt-master.md`）。

**一定要修**
- 東西超出畫布、文字超出它的框、兩段文字重疊、圖形互相壓到。
- 對比不夠：小字對比低於 4.5，24 px 以上的字低於 3；字直接壓在複雜的圖上。
- 頁首、進度條、頁碼被蓋住或不見。
- 頁面清單裡寫的主要元素沒有出現。

**明顯不好看才修**（拿不定就不動，避免改來改去）
- 同一段文字行距太擠（小於字級 1.05 倍）或中間空一大塊。
- 同一欄的左緣、同一列的基線差超過 4 px。
- 一排卡片間距不一樣。
- 中文字距太大（超過字級的 5%）。
- 最顯眼的東西不是這頁要強調的那個。
- 太多顏色在搶注意力。

**不要在這一步動的**：配色與字體（那是主題的決定）、欄數或圖表類型（那是版型的決定）、文字內容（那是講稿和事實的決定）。

## 不要做

- 一頁兩張主圖、整頁文字牆、卡片內四行以上內文。
- 用顏色當唯一的區分（虛線、文字標籤也要有）。
- 在投影片上放未標範圍的數字。
